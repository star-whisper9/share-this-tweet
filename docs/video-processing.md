# 动态拼图与画框（实验）

此功能已接入开发版，尚未发布到 AMO 或 GitHub Release。

## 操作

先在设置的实验性功能页启用动态处理并保存。默认关闭；关闭时隐藏动态画框及含动态素材的拼图按钮，后台也会拒绝新动态任务。纯图片拼接、静态卡片、原文件和写入来源仍可使用。已开始的任务可继续或手动取消。

- 推文有 GIF／视频时，“拼接全部媒体”输出 MP4；只有照片时，继续使用原来的图片拼接。
- 拼图的来源条跟随“照片 / 拼图”行里的原图、上框或下框；间隔仍使用设置页的无缝／画廊选项。
- 单项视频和 GIF 在动态媒体行选择上框或下框，再保存媒体。原文件、写入来源仍保留，不经过转码。
- 图片／网格卡片／单行卡片仍为静态输出。
- 处理过程中显示下载、加载、探测和编码进度，可取消。确认入队后，切换推文或关闭原页面不会取消任务，进度和取消操作位于独立任务页。

## 首版规则

静态图全程不动，所有动态项同时开始，以最长动态项的时长结束，较短项停在末帧。只保留第一条实际带音轨的普通视频的声音，音轨不足的部分补静音；GIF 不提供声音。输出 H.264 / yuv420p MP4，音轨为 AAC。

设置提供输入总大小、最长动态项时长、单项源图像／最终输出（含画框）像素数、输出帧率四种上限。超限时明确提示：动态画框回退为原媒体，复用已下载文件；动态拼图回退为静态拼图，动态项使用已有预览图。只针对这些限制回退，下载失败、解码错误等仍报错。大小限制约束转码输入；画框回退仍需要完成原文件下载。

单项设为 0 表示不限。默认采用标准配置：256 MiB、180 秒、4,147,200 像素、30 fps。另有保守（64 MiB／30 秒／2,073,600 像素／30 fps）、高清（512 MiB／600 秒／8,294,400 像素／60 fps）及不限配置。这是扩展的处理保护设置，不是 X 账号配额，也不保证浏览器能处理所有上限内素材。

图片按最矮素材的高度横排，保留宽高比并取偶数像素；输出帧率采用动态素材中的最高帧率，探测不到有效帧率时使用 24 fps。

保留最多 4 项素材及单个 FFmpeg 任务的约束；旋转元数据和非方形像素素材仍暂不支持。FFmpeg 探测、编码及整项任务均不再设置自动超时，需手动取消；从任务页取消仍会终止 Worker 并释放资源；关闭原推文页面不会取消已入队任务。浏览器 Canvas、WASM 内存和编码器本身的限制仍可能导致大素材失败。

## 实现

内容脚本先将推文、媒体选择和设置快照提交到持久化任务队列，后台确认入队后独立处理。后台检查媒体域名及下载完整性，再把 Blob 交给单线程 Worker。Worker 用真实 ffprobe 读取尺寸、时长和音轨，返回画框所需宽度；后台复用 Canvas 来源条渲染后，将 PNG 回传给 Worker 一并编码。

`@ffmpeg/core` 固定为 0.12.10，其 JavaScript/WASM 在构建时复制到扩展自身目录，不从 CDN 加载。CSP 仅增加 `wasm-unsafe-eval`。核心 WASM 未压缩约 31 MiB，因此安装包会明显变大；首次动态操作才加载引擎，结束后释放 Worker。

- `src/core/video-plan.ts`：尺寸、时长、音轨选择和 FFmpeg 参数。
- `src/core/video-engine.ts`：探测、布局、帧条握手和编码。
- `src/workers/video-render.worker.ts`：加载本地核心、完整 ffprobe JSON、错误日志与进度。
- `src/background/video-render.ts`：下载边界、排他处理、Canvas 画框和取消。
- `src/core/job-renderer.ts`：按任务快照渲染、收集诊断与处理超限回退。
- `src/background/export-jobs.ts`：持久化队列、保存与任务取消；详见[后台任务说明](background-jobs.md)。

第三方来源和许可证见 `src/vendor/ffmpeg/NOTICE.txt`，构建会随核心打包。

## 验证

`npm run check` 验证类型、单元测试与构建；`npm run lint:extension` 检查扩展清单。

本机安装 `ffprobe` 后，可运行 `npm run verify:video`。它在 Node Worker 中执行打包后的真实 ffmpeg.wasm Worker，模拟浏览器的本地资源加载，验证混合拼接、GIF 画廊加下框、单视频上框／下框的 MP4 尺寸、时长、帧率和音轨。此检查不等于 Firefox 扩展实机或手机性能测试。

人工回归：在桌面及 Android Firefox 分别测试短 GIF + 照片、带声音视频上下画框、取消后再导出、较长素材的处理及手动取消，以及原文件／写入来源没有被改为转码。

## 性能诊断

每次动态任务可从“导出任务”页点击“下载诊断 JSON”保存当前报告。不同任务分别保留报告；同一批媒体中有多次动态处理时，保留最后一次处理的报告。移除任务也会移除其诊断。

报告包含：

- FFmpeg 核心版本、浏览器版本、媒体序号、实际探测的尺寸／帧率／时长／音轨，以及本次完整编码参数。
- 下载、引擎加载、写入素材、探测、画框准备、编码、MP4 fast-start 索引整理、读取输出、复制输出和清理的耗时。
- 约每两秒一次的完整 FFmpeg 进度块：已编码秒数、帧数、平均及最近窗口速度／fps、原始进度比例。
- WASM 线性内存容量与峰值、MEMFS 输入文件大小、输出文件逻辑大小与输出缓冲容量、显式输出副本大小。

**容量不是实际已使用内存，也不是 Firefox 进程总内存。** WASM 容量不包括所有 JavaScript 缓冲或浏览器开销。输出副本与 MEMFS 容量分开记录，不相加冒充总内存。系统内存压力与交换量需要结合 macOS 活动监视器观察。

只记录参数、计数和容量，不保存媒体帧、推文正文或媒体下载地址。最多保留最近 2000 条样本，超出时在 `droppedSamples` 中明确计数；阶段耗时汇总继续保留。取消或失败也可下载已收到的样本。

`finalizing` 专指 FFmpeg 日志报告的 MP4 索引整理阶段；输出读取和副本创建分别计时。日志采样在同步 WASM 调用内部由 FFmpeg 回调触发，不依赖会被编码阻塞的 JavaScript 定时器。诊断选项只增加日志输出，不改变编码预设、CRF、帧率或尺寸。

## 耗时计算器和 X 视频规格调查

计算器输入最终画面宽高、时长（秒）、帧率和输入平均码率（Mbps）。动态拼图按完整横排画布填写尺寸，包含间隔和来源画框，以最长动态项时长及最高动态帧率估算。码率用于估算输入体积，不用于推测输出体积或直接决定编码耗时；多素材实际总下载量应合计各输入文件。

参考环境为 **Apple M4 Firefox Desktop**，单线程 ffmpeg.wasm、libx264 ultrafast / CRF 23。本次三份诊断的编码吞吐量约为 16.6、22.9、19.2 百万像素帧/秒。为覆盖内容和机器状态波动，估算采用 10–30 百万像素帧/秒：`耗时范围 = 0.3 + 宽 × 高 × fps × 秒数 / (30e6 到 10e6)`。体积按 `Mbps × 1e6 × 秒数 / 8` 换算。估算不含网络下载；源素材解码、拼接、温度、浏览器负载可能令实际耗时超出范围，尤其是长片和大画布。它不预测内存占用，也不是性能承诺。

调查日期：2026-09-19。

- [X 视频帮助](https://help.x.com/en/using-x/x-videos)列出非 Premium 上传上限为 140 秒、512 MB。这些是上传约束，不是下载文件码率或本扩展的处理能力。
- [Premium 长视频帮助](https://help.x.com/en/using-x/premium-longer-videos)列出 Web/iOS 最长 4 小时、16 GB，Android 最长 10 分钟；页面同时写有“4 小时 1080p”和“超过 2 小时必须 720p”，描述不完全一致。不能据此保证任意 4 小时视频均可使用 1080p，或认为普通账号永远只提供 720p。该页也说明平台会调整分辨率及码率。
- [X/Twitter 2020 年工程文章](https://blog.x.com/engineering/en_us/topics/infrastructure/2020/introducing-vmaf-percentiles-for-video-quality-measurements)给出了用于实验的编码阶梯：480p30／1.25 Mbps、720p30／2.5 Mbps、1080p30／5 Mbps。这是历史实验示例，不是当前所有推文固定采用的档位表。

计算器提供上述三类画面参考，以及 1080p 长视频场景；数值可改，明确属于历史示例／估算预设。Premium 资格、上传码率、播放器清晰度与实际下载 MP4 参数不能互相代替，应优先填写实际媒体元数据。
